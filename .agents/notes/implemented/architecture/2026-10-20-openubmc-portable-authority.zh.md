# Agent Note: 可移植 openUBMC Session 授权

Status: implemented

[English](2026-10-20-openubmc-portable-authority.md) | 中文

## 问题

可安装的 openUBMC bundle 不能要求官方 DSH Host 修改 MCP 派发或识别自定义必需事件。重放时丢弃授权或断线后丢失操作标识，可能放行未授权续接或重复设备副作用。

## 决策

可移植提供方使用公开的工具、命令、提示、提问和投影 API。它与[原生集成](2026-10-19-openubmc-native-run-authority.zh.md)共享 `createRuntimeController`，保留唯一的 Run 归属、权限、Gate 绑定及未知调用恢复实现。Runtime 独占领域状态转换和设备变更日志。

私有版本化记录将可信 Session 绑定到权限、已返回 Run 和未完成调用。文件名散列 Session 标识，校验后的内容保留该标识。写入使用排他随机临时文件、仅所有者权限、文件同步、原子替换和目录同步。跨进程写锁串行化更新；独立执行租约阻止调用与恢复重叠，同时允许撤权。仅支持同一宿主和 PID 命名空间中的写入者。Fork 使用独立记录，不继承授权。私有记录缺失时，Host 投影识别已有执行；此时数据缺失或损坏会拒绝继续。

插件自有 MCP 提供方在派发前注入 Session 与操作元数据。标准工具结果通过公开的派发包装 API 保留完整失败 JSON 和原生失败状态。Host 日志不追加自定义 openUBMC 事件。提示上下文仍由 Host 记录。断开的传输在显式调用时重连；副作用不会自动重放。未获响应的 start 保留原操作标识，仅供用户授权后的精确恢复。

## 已考虑的替代方案

**要求定制 Host。** 这会阻止安装到已验证的官方发行版，并将插件交付耦合到 Host 发布。原生开发配置单独保留该集成。

**将授权事件标为 ignorable 或修改 Host 事件目录。** 事件生产者缺失时会静默丢弃授权，动态注册则让 Session 可读性取决于当前组合。派发始终要求私有授权数据，并将其与 Runtime 状态和 Session 一并备份。

**从模型参数或 fork 历史重建执行权限。** 二者都不是可信授权。已有执行后，私有状态缺失不会允许接管或新增副作用。

## 影响

官方 Host 发行版逐一通过归档安装测试，optional peers 仅列出通过验证的完整版本。生命周期检查覆盖工具发现、结构化失败、重新挂载、更新、恢复和私有数据保留。协议测试覆盖精确授权、外部与 fork 隔离、取消、Gate 绑定和恢复。这些检查使用离线协议端点，不验证设备传输或固件。旧自定义事件 Session 保留在其兼容 Host；可移植插件使用新 Session，不跨读取器转换授权。
